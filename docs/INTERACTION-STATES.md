# Yozora interaction and state-machine inventory

**Scope:** source-based inventory of the control panel, its authenticated local HTTP endpoints, and the major daemon state machines called out in the README and audit. “Covered” below means exercised by a synthetic browser or injected/unit test; it does not mean a real Windows/service transition passed. Requests can still fail because of authorization, invalid input, file/config errors, service refusal, process shutdown, or native OS failures.

## Control panel states

| Area | States and transitions | Failure, cancellation, and recovery | Verification boundary |
| --- | --- | --- | --- |
| Panel state poll | Initial loading → live state; live track → paused/playing/idle; live → stale after failed or timed-out request → automatic retry on the next one-second tick → recovered. A last successful preview remains visible and is marked stale. | A request has a five-second abort. Before any successful response, the UI shows waiting/offline copy; after one, it keeps the last preview and shows an offline note. Links retain focus when unchanged. | Synthetic suite covers initial offline, panel offline, recovery, playing/paused, focus retention, CSP and console. No native panel-host test. |
| Media session selection | Each supported session is observed; eligible enabled sources are arbitrated by the saved six-source order. If the winning session stops or is blocked, the next eligible source wins. A hidden winning track is suppressed rather than replaced by a lower-priority session. | Detection gaps clear/refresh selection through daemon policy; disabling a source revokes its current publication. Source-specific failures and stale async work need Windows/injected checks. | README and state audit describe policy; injected tests cover selected backend races. Real SMTC/source arbitration remains a Windows check. |
| Discord publication | Disconnected → retry wait → connected → publish after debounce/send-rate gate; track/presentation changes or connection loss make the current visible state eligible for republish. Paused/hidden/blocked/idle policy may clear or suppress. | Discord unavailable, failed handshakes, application-ID mismatch, rate limit or send error are surfaced through status/error state and retried according to daemon policy. A local test card can be unconfirmed because remote profile visibility is not observable. | The native named-pipe path is not exercised by this browser fixture. State audit and private-pipe tests are separate from live Discord. |
| Artwork and classification | Track change starts asynchronous artwork/classification work; a matching current result enriches the dashboard/card. Cache hit reuses a result. | Configuration loading | Valid config → active settings; valid save/reload → new settings; malformed edit while running → retain prior active config; malformed startup file with a valid last-good copy → restore copy, preserve broken file and show dismissible notice; no usable backup → startup error. | Panel notice can be dismissed for that restore; another restore can show it again. | Process/tray lifecycle | Launching the executable opens panel and starts/reuses daemon; daemon owns tray; closing the panel exits only the short-lived panel; tray open launches panel; tray Quit stops daemon and panel. ## Panel HTTP surface

Every authenticated endpoint requires the current run token in query parameter `t` (or `X-Uika-Token` where the handler accepts auth). The server binds to `127.0.0.1`; the root page also requires the token. The table lists the panel's current method use, not a promise that the handlers cannot fail.

| Path | Methods used by panel | Purpose / notable failure behavior |
| --- | --- | --- |
| `/` | GET | Render embedded panel with nonce CSP. Invalid token, unsupported method, nonce failure, template parse failure can fail the request. |
| `/fonts/{name}.woff2` | GET | Serve exact embedded font names only; unknown path/name is 404; other methods are rejected. |
| `/api/state` | GET | One-second dashboard/setup/Spotify/pause/config-restore state poll. A request timeout/error produces stale/offline UI. |
| `/api/sources` | GET, POST | Settings and order. Strict payload validation; stale conditional write returns 412. |
| `/api/autostart` | GET, POST | Startup state; requires strict boolean body; Windows autostart operation may return 500. |
| `/api/appearance` | GET, POST | Theme/motion/language; invalid or empty body rejected; config load/save/reload may fail. |
| `/api/setup` | GET, POST | Checklist completion and app ID; strict config changes can fail. |
| `/api/test-card` | POST | Start test activity; 409 when another test is active; Discord engine may fail asynchronously. |
| `/api/spotify` | POST | Begin/cancel/disconnect Spotify authorization; invalid action/client ID, browser launch, callback, storage or authorization errors are surfaced. |
| `/spotify/callback` | GET | OAuth callback authorizes using the single-use state token instead of the panel token. Wrong/replayed/superseded state returns 400; provider failure 502; config-save failure 500; successful ordered commit 200. |
| `/api/pause` | POST | Pause/resume sharing; invalid duration/action or engine failure is rejected. |
| `/api/card` | GET, POST | Read or atomically apply card config; invalid fields/templates and config failures are rejected. |
| `/api/card/preview` | POST | Validate and render proposed card without saving; malformed template returns an error. |
| `/api/hidden` | GET, POST | List/add/remove hidden rules; invalid or over-limit rules/config failures are rejected. |
| `/api/update` | GET | Current release/install state. Update service may be unavailable or report an error state. |
| `/api/update/install` | POST | Begin updater; duplicate/inapplicable installs are refused; download/verification/install may fail. |
| `/api/diagnostics` | GET | Plain-text sanitized report; can fail due to authorization or server errors. |
| `/api/recent` | GET | In-memory recently published tracks; empty after restart. |

`GET /api/spotify` also returns authorization status to authenticated callers. Embedded fonts support HEAD as well as GET. A separate loopback artwork server serves `/art/{name}`; it checks the requested basename before serving cached content. Missing/evicted files return errors and the panel uses its fallback. Artwork serving is local and does not imply Discord can reach a loopback image.

| Owner | States, guards and terminal outcomes | Evidence and residuals |
| --- | --- | --- |

| Player arbitration and presence engine | Snapshot arrival/withdrawal → eligible winner → debounce → rate-gated publish or policy clear; idle expiry, pause timer, hidden/block policy and shutdown alter eligibility | Existing injected presence/player tests pass in the shadow. Actual media and Discord profile outcomes remain live work. |
| Discord IPC | Disconnected → dial/handshake → connected; source app change or read/write error → close/retry; request timeout/close ends pending operations | Private-pipe tests cross-compile; the Linux shadow replaces dial and excludes pipe integration tests. |
| Spotify Link | Idle → waiting → exchanging → generation-validated pre-store stop → token store → config/poller commit; denial, expiry, cancel, replacement and replay end or invalidate the operation | Barrier-based injected tests cover supersession and ordering. | Spotify Manager/Provider | Stopped → starting → token/refresh → poll → latest-value snapshot; 204 withdraws playback; auth/network failure reports error; stop waits for in-flight request then withdraws snapshot | Injected queue/stop tests pass; HTTP operations retain the existing ten-second timeout. | Recent/hidden/test card | Successful eligible publication records/deduplicates bounded recent history; hidden/paused/test states suppress inappropriate recording; test card accepted → sending/shown/confirmed/unconfirmed/error | Existing injected tests cover selected transitions. | Startup/shutdown and installer | Endpoint/PID validation → daemon reuse/start → panel ownership; quit/stop validates executable identity; upgrade stops old process, replaces files and conditionally restarts; uninstall retains/purges by explicit choice | Native sysutil/tray/window/installer tests cross-compile. Process races, stale PID reuse, sign-in, WebView2 and installer behavior remain Windows smoke tests. |

This inventory names the machines reviewed in this pass. Environmental errors have deliberate outcomes and recovery paths, but the available tests do not enumerate every possible native or provider interleaving.

## Verification limits

The panel's 53-check suite proves selected browser behaviors with a synthetic local API. It does not exhaust every handler status code or failure source. The backend Go tests, Linux shadow test and Windows-native integration gates are separate.
